# API обходного листа: полный справочник для бэкенда

Этот документ описывает каждый запрос, который делает фронтенд: кто его отправляет, что лежит в теле, что вернуть, какие ошибки возможны и что фронт делает с ответом. Всё сверено с кодом фронта (`frontend/src/infrastructure/httpApi.ts`, `frontend/src/application/ports.ts` и страницы в `frontend/src/presentation/`).

Три документа дополняют друг друга:

| Документ | Что в нём | Когда открывать |
|---|---|---|
| `docs/backend/API.md` (этот) | Каждый эндпоинт подробно, с примерами | Пишете обработчик |
| `docs/backend/openapi.yaml` | Машиночитаемый контракт: схемы и коды | Генерируете типы, валидируете запросы, смотрите в Swagger UI |
| `docs/backend/README.md` | Модель данных (SQL), бизнес-правила R1–R20, права, безопасность, Telegram, импорт | Проектируете базу и проверяете правила |

Номера правил вида **R8** ведут в раздел 4 файла README.md. Если какие-то документы противоречат друг другу, правильным считается openapi.yaml. Сообщите о расхождении, и мы поправим остальные.

## 1. Порядок работы: что делать первым

Так фронт оживает по частям, и каждую часть можно показать, не дожидаясь остальных.

| Шаг | Эндпоинты | Что заработает на фронте |
|---|---|---|
| 1 | `POST /auth/login`, `GET /auth/me`, `POST /auth/logout` | Вход, выход, защита кабинетов |
| 2 | `GET /sheets/mine` | Кабинет студента |
| 3 | `GET /sheets`, `GET /queue/counts`, `PUT /sheets/{number}/marks/{department}` | Очередь отдела, отметки, долги |
| 4 | `GET /sheets/summary`, `POST /sheets`, `GET /templates`, `GET /students` (поиск) | Учебная часть открывает листы |
| 5 | `GET /sheets/{number}` | Карточка листа с журналом |
| 6 | `GET /public/verify/{number}` | Проверка подлинности по QR |
| 7 | `POST /auth/password` | Смена пароля, первый вход с временным паролем |
| 8 | `/students`, `/students/import`, `/users`, `/users/{id}/reset-password` | Справочники учебной части |
| 9 | `PUT /templates/{type}`, `GET /audit`, `POST /queue/clear` | Шаблоны, журнал, массовая отметка |
| 10 | `/telegram/link` и бот | Уведомления |

Для шагов 1–3 нужны таблицы `users`, `students`, `sheets`, `marks`, `sessions`, `audit_log`. SQL целиком лежит в README.md, раздел 3.

## 2. Общие соглашения

### 2.1. Адрес и окружение

- Все пути в этом документе начинаются с `/api/v1`. Полный адрес отметки, например: `PUT /api/v1/sheets/2026-0142/marks/library`.
- В разработке фронт работает на `http://localhost:5173`, а Vite проксирует всё, что начинается с `/api`, на `http://localhost:8000`. Поднимайте бэкенд на порту 8000 или поменяйте `VITE_PROXY_TARGET` в `frontend/.env`.
- В проде фронт и API живут на одном домене: nginx отдаёт статику фронта и проксирует `/api` на бэкенд. CORS тогда не нужен.

### 2.2. Что фронт присылает в каждом запросе

```http
GET /api/v1/sheets/mine HTTP/1.1
Accept: application/json
X-Requested-With: fetch
Cookie: session=Qm9hcmQtZGVjay1maW5hbC12MTI...
```

- `X-Requested-With: fetch` приходит в **каждом** запросе, включая GET. На изменяющих запросах (POST, PUT, PATCH, DELETE) без этого заголовка отвечайте `403 forbidden`. Это защита от CSRF вместе с `SameSite=Lax`.
- `Content-Type: application/json` стоит, когда есть JSON-тело. Импорт CSV приходит как `multipart/form-data`, и `Content-Type` с границей частей ставит сам браузер.
- Cookie браузер отправляет сам. Фронт её не видит и не читает.

### 2.3. Сессия

| Параметр | Значение |
|---|---|
| Имя cookie | `session` |
| Флаги | `HttpOnly; Secure; SameSite=Lax; Path=/` |
| Значение | 32 случайных байта в base64url. В базе храните только `sha256` от него |
| Срок | 12 часов, продлевается при каждом запросе; абсолютный максимум 7 дней |
| Ставится | ответом на `POST /auth/login` |
| Снимается | ответом на `POST /auth/logout`: `Set-Cookie: session=; Max-Age=0; Path=/` |

На localhost без HTTPS флаг `Secure` не даст браузеру сохранить cookie. В режиме разработки уберите `Secure` через переменную окружения, в проде оставьте.

### 2.4. Формат данных

- Тела запросов и ответов в JSON, кодировка UTF-8.
- Момент времени отдавайте в ISO 8601 с часовым поясом: `2026-10-29T10:15:00+05:00` или `2026-10-29T05:15:00Z`. Фронт делает `new Date(значение)`, строка без пояса прочитается как местное время браузера и съедет.
- Дата без времени (срок долга `due`) в формате `YYYY-MM-DD`.
- Колледж живёт по `Asia/Almaty`. Слово «сегодня» в правилах значит дату в этом поясе, а не в UTC. С 00:00 до 05:00 по Алматы в UTC ещё вчера, и проверка «срок не в прошлом» ошибётся, если считать по UTC.
- Пустое необязательное поле можно не присылать совсем или прислать `null`. Фронт понимает оба варианта.

### 2.5. Ответ без тела

`204 No Content` отдавайте **без тела**. Фронт на 204 не пытается читать JSON. На все остальные статусы, включая ошибки, отдавайте JSON.

### 2.6. Пагинация

Списки принимают `page` (с 1) и `pageSize` (1–100, по умолчанию 25) и отвечают так:

```json
{ "items": [ ... ], "total": 137 }
```

- `total` — сколько всего записей подходит под фильтр, а не сколько вернулось на странице. По нему фронт рисует «Страница 2 из 6».
- Страница за пределами списка возвращает `{ "items": [], "total": 137 }`, без ошибки.
- Сколько фронт просит на страницу: очередь отдела и листы 25, студенты 25, сотрудники 50, журнал 50, поиск студента при открытии листа 8.

### 2.7. Поиск `q`

- Обрежьте пробелы по краям. Пустая строка значит «без поиска».
- Ищите подстроку без учёта регистра (`ILIKE '%' || q || '%'` в PostgreSQL).
- Где ищем: в листах по ФИО студента, группе и номеру листа; в студентах по ФИО, группе и логину.
- Фронт шлёт `q` с задержкой 300 мс после последнего нажатия клавиши.

### 2.8. Ошибки

Любая ошибка выглядит так:

```json
{
  "error": {
    "code": "note_required",
    "message": "Debt requires a note",
    "field": "note"
  }
}
```

| Поле | Обязательно | Что значит |
|---|---|---|
| `code` | да | Машинный код из списка ниже. Фронт показывает свой перевод по коду |
| `message` | да | Текст для логов и разработчика. Пользователь его не видит |
| `field` | нет | Поле формы, к которому относится ошибка. Фронт подсвечивает это поле |

Значения `field`, которые фронт подсвечивает: `name`, `login`, `group`, `departmentId`, `note`, `due`, `current`, `next`, `type`.

| Код | HTTP | Когда | Что увидит пользователь |
|---|---|---|---|
| `validation` | 400 | Тело не прошло схему: не тот тип, длина, формат | «Проверьте заполнение полей.» |
| `unauthorized` | 401 | Нет сессии, сессия истекла, пользователь заблокирован | Фронт отправит на вход |
| `login_failed` | 401 | Неверный логин или пароль, либо заблокирован (причину не уточнять) | «Неверный логин или пароль.» |
| `forbidden` | 403 | Роль не позволяет, нет `X-Requested-With`, попытка заблокировать себя | «У вашей роли нет доступа к этому действию.» |
| `not_found` | 404 | Нет объекта или у роли нет к нему доступа | «Не найдено. Возможно, запись удалили…» |
| `duplicate` | 409 | У студента уже открыт лист этого типа (R2) | «У студента уже есть открытый лист этого типа…» |
| `closed` | 409 | Лист закрыт, менять нельзя (R7) | «Лист уже закрыт, отметки в нём менять нельзя.» |
| `login_taken` | 409 | Логин занят (R15) | «Такой логин уже занят…» |
| `foreign_dept` | 400 | Отдел не входит в лист (R6) | «Ваш отдел не входит в этот лист.» |
| `note_required` | 400 | Долг без описания (R8) | «Опишите задолженность…» |
| `note_too_long` | 400 | Описание длиннее 200 символов (R8) | «Описание длиннее 200 символов…» |
| `due_past` | 400 | Срок раньше сегодня (R8) | «Срок не может быть в прошлом.» |
| `no_depts` | 400 | Пустой шаблон (R13) | «В шаблоне должен остаться хотя бы один отдел.» |
| `department_required` | 400 | Сотрудник отдела без отдела (R16) | «Выберите отдел сотрудника.» |
| `weak_password` | 400 | Новый пароль короче 8 символов (R17) | «Пароль должен быть не короче 8 символов.» |
| `wrong_password` | 400 | Неверный текущий пароль (R17) | «Текущий пароль введён неверно.» |
| `bad_file` | 400 | CSV целиком не читается | «Файл не прочитан. Нужен CSV в UTF-8…» |
| `rate_limited` | 429 | Превышен лимит; нужен заголовок `Retry-After` в секундах | «Слишком много попыток. Подождите минуту…» |
| `server` | 500 | Всё непредвиденное. Подробности только в лог | «На сервере ошибка…» |

Отдавайте **только** коды из этой таблицы. Фронт знает переводы ровно для них. Если нужен новый код, сначала договоримся, потом фронт добавит перевод.

### 2.9. Как фронт реагирует на статусы

- **401** на любом запросе, кроме `GET /auth/me` и `POST /auth/login`, значит, что сессия умерла посреди работы. Фронт отправляет человека на `/login?next=<текущая страница>` и после входа возвращает обратно.
- **401** на `GET /auth/me` — обычное «не вошёл», фронт просто показывает вход.
- **Сеть недоступна** (запрос не дошёл) — фронт пишет «Нет связи с сервером» и даёт кнопку «Повторить».
- **5xx** — «На сервере ошибка». Данные на экране фронт не меняет, введённое в форму не теряется.

## 3. Справочник значений

### 3.1. Отделы `DeptId`

Порядок в этой таблице — канонический. В этом порядке отдавайте отметки внутри листа и отделы в шаблонах.

| Код | Русский | Казахский | Кабинет по умолчанию (фронт показывает студенту) |
|---|---|---|---|
| `library` | Библиотека | Кітапхана | Каб. 104, пн–пт 9:00–17:00 |
| `accounting` | Бухгалтерия | Бухгалтерия | Каб. 210, пн–пт 9:00–16:00 |
| `dorm` | Общежитие | Жатақхана | Общежитие, 1 этаж, комендант |
| `military` | Военно-учётный стол | Әскери есеп үстелі | Каб. 118, вт и чт 10:00–15:00 |
| `it` | IT-отдел | IT бөлімі | Каб. 305, пн–пт 9:00–18:00 |
| `academic` | Учебная часть | Оқу бөлімі | Каб. 201, пн–пт 9:00–17:00 |

Названия и кабинеты фронт хранит у себя, бэкенд присылает только код.

### 3.2. Типы листа `SheetType`

| Код | Русский | Отделы по умолчанию |
|---|---|---|
| `graduation` | Выпуск | все шесть |
| `expulsion` | Отчисление | все шесть |
| `transfer` | Перевод | library, accounting, it, academic |
| `leave` | Академический отпуск | library, accounting, academic |
| `dorm` | Выселение из общежития | dorm, accounting |

### 3.3. Состояние отметки `MarkState`

| Код | Значит | Как выглядит у студента |
|---|---|---|
| `pending` | Отдел ещё не смотрел | Пунктирный круг, «Отдел ещё не проверил лист. Приходить не нужно.» |
| `clear` | Задолженности нет | Синий круг с галочкой |
| `debt` | Есть долг | Красный круг с «!», описание, срок, кабинет |

### 3.4. Статус листа `SheetStatus`

Статус не хранится в базе, а вычисляется при каждом ответе (R11):

```
если closedAt заполнен            → closed
иначе если есть хоть один debt    → debt
иначе если есть хоть один clear   → progress
иначе                             → created
```

### 3.5. Роли `Role`

| Код | Кто | Домашняя страница после входа |
|---|---|---|
| `student` | Студент | `/student` |
| `officer` | Сотрудник отдела | `/office` |
| `admin` | Учебная часть | `/admin` |

## 4. Объекты

### 4.1. `User`: кто вошёл

```json
{
  "id": "6f1c2a9e-3b7d-4e0a-9c55-2d8f1b0e7a41",
  "name": "Гульнара Нуртазина",
  "login": "g.nurtazina",
  "role": "officer",
  "departmentId": "library",
  "active": true,
  "telegramLinked": false,
  "mustChangePassword": false
}
```

| Поле | Тип | Обязательно | Что значит и где использует фронт |
|---|---|---|---|
| `id` | string | да | По нему фронт прячет у администратора кнопки «Заблокировать» и «Новый пароль» в его собственной строке |
| `name` | string | да | Шапка кабинета, заголовок аккаунта |
| `login` | string | да | Аккаунт, таблица сотрудников |
| `role` | `Role` | да | Какие разделы показывать |
| `departmentId` | `DeptId` | у `officer` | Очередь отдела строится по нему. У `officer` поле обязано быть, иначе кабинет отдела не откроется |
| `studentId` | string | у `student` | Связь со студентом |
| `group` | string | у `student` | Аккаунт студента |
| `active` | boolean | да | В таблице сотрудников: «Активен» / «Заблокирован» |
| `telegramLinked` | boolean | да | Студенту показываем «Подключено» или кнопку «Подключить» |
| `mustChangePassword` | boolean | да | `true` — фронт пускает только на `/account`, пока пароль не сменят |

### 4.2. `Student`: запись справочника

```json
{
  "id": "c0a8012e-5d3b-4b8e-8f0a-1e2d3c4b5a69",
  "userId": "9b2e4f61-7a3c-4d5e-8f90-a1b2c3d4e5f6",
  "name": "Айгерим Сапарова",
  "group": "ПО-2201",
  "login": "a.saparova",
  "activeSheets": 1
}
```

| Поле | Тип | Обязательно | Что значит |
|---|---|---|---|
| `id` | string | да | Его фронт передаёт в `POST /sheets` как `studentId` |
| `userId` | string | да | Учётная запись студента. По ней фронт сбрасывает пароль: `POST /users/{userId}/reset-password` |
| `name` | string | да | ФИО (хранится в `users.name`) |
| `group` | string | да | 2–20 символов |
| `login` | string | да | Логин студента |
| `activeSheets` | integer | да | Сколько у студента открытых листов. Показывается в справочнике |

### 4.3. `Mark`: отметка отдела в листе

```json
{
  "department": "library",
  "state": "debt",
  "note": "Вернуть книгу «Python. Основы программирования», инв. № 4471",
  "due": "2026-11-05",
  "at": "2026-10-28T09:15:00+05:00",
  "by": "Гульнара Нуртазина"
}
```

| Поле | Тип | Когда есть | Что значит |
|---|---|---|---|
| `department` | `DeptId` | всегда | Чья отметка |
| `state` | `MarkState` | всегда | Состояние |
| `note` | string | только при `debt` | Что вернуть или оплатить, 1–200 символов |
| `due` | `YYYY-MM-DD` | только при `debt`, если задан | До какого числа |
| `at` | дата-время | при `clear` и `debt` | Когда поставили отметку. Отметку моложе минуты фронт подсвечивает как свежую |
| `by` | string | при `clear` и `debt` | ФИО сотрудника **на момент отметки**. Переименование сотрудника потом не меняет старые отметки |

У `pending` есть только `department` и `state`.

### 4.4. `Sheet`: обходной лист

```json

  "number": "2026-0142",
  "type": "graduation",
  "status": "debt",
  "createdAt": "2026-10-26T09:00:00+05:00",
  "closedAt": null,
  "student": { "id": "c0a8012e-5d3b-4b8e-8f0a-1e2d3c4b5a69", "name": "Айгерим Сапарова", "group": "ПО-2201" },
  "marks": [
    { "department": "library", "state": "debt", "note": "Вернуть книгу «Python. Основы программирования», инв. № 4471", "due": "2026-11-05", "at": "2026-10-28T09:15:00+05:00", "by": "Гульнара Нуртазина" },
    { "department": "accounting", "state": "clear", "at": "2026-10-27T10:15:00+05:00", "by": "Евгений Ким" },
    { "department": "dorm", "state": "clear", "at": "2026-10-27T11:15:00+05:00", "by": "Серик Байжанов" },
    { "department": "military", "state": "clear", "at": "2026-10-28T12:15:00+05:00", "by": "Андрей Петренко" },
    { "department": "it", "state": "pending" },
    { "department": "academic", "state": "clear", "at": "2026-10-29T14:15:00+05:00", "by": "Жанар Абдрахманова" }

```

| Поле | Тип | Обязательно | Что значит |
|---|---|---|---|
| `number` | string | да | `YYYY-NNNN`: год открытия и номер внутри года с ведущими нулями (R4). Это же значение стоит в QR и в URL |
| `type` | `SheetType` | да | Тип |
| `status` | `SheetStatus` | да | Вычисленный статус (раздел 3.4) |
| `createdAt` | дата-время | да | Когда открыт |
| `closedAt` | дата-время или `null` | да | Когда закрыт. `null`, пока открыт |
| `student` | объект | да | `id`, `name`, `group` студента |
| `marks` | `Mark[]` | да | Только отделы этого листа, в каноническом порядке (раздел 3.1) |

### 4.5. `AuditEntry`: запись журнала

```json
{ "at": "2026-10-28T09:15:00+05:00", "actor": "Гульнара Нуртазина", "sheet": "2026-0142", "department": "library", "action": "debt", "note": "Вернуть книгу «Python. Основы программирования», инв. № 4471" }
```

| Поле | Тип | Когда есть | Что значит |
|---|---|---|---|
| `at` | дата-время | всегда | Когда |
| `actor` | string | всегда | ФИО на момент действия, либо `Система` для автозакрытия |
| `sheet` | string | всегда | Номер листа |
| `department` | `DeptId` | у `clear` и `debt` | Чья отметка |
| `action` | `create` / `clear` / `debt` / `close` | всегда | Открыт лист, нет долга, долг, лист закрыт автоматически |
| `note` | string | у `debt` | Описание долга |

### 4.6. `Templates`: шаблоны

```json
{
  "graduation": ["library", "accounting", "dorm", "military", "it", "academic"],
  "expulsion": ["library", "accounting", "dorm", "military", "it", "academic"],
  "transfer": ["library", "accounting", "it", "academic"],
  "leave": ["library", "accounting", "academic"],
  "dorm": ["dorm", "accounting"]
}
```

Всегда все пять ключей, у каждого хотя бы один отдел, отделы в каноническом порядке.

### 4.7. `Verification`: результат публичной проверки

Набор полей зависит от ответа:

```json
{ "found": false, "closed": false }
```

```json
{ "found": true, "closed": false, "shortName": "Айгерим С." }
```

```json
{
  "found": true,
  "closed": true,
  "shortName": "Данияр Ж.",
  "number": "2026-0139",
  "type": "graduation",
  "closedAt": "2026-10-28T15:40:00+05:00",
  "departments": ["library", "accounting", "dorm", "military", "it", "academic"]
}
```

`shortName` — имя и первая буква фамилии. Никогда не отдавайте здесь полное ФИО, группу, описания долгов и суммы (R20).

## 5. Вход и аккаунт

### 5.1. `POST /auth/login` — вход

**Кто:** все, без сессии. **Экран:** `/login`.

Тело:

```json
{ "login": "g.nurtazina", "password": "my-secret-pass" }
```

| Поле | Ограничения |
|---|---|
| `login` | строка до 64 символов; фронт обрезает пробелы по краям |
| `password` | строка до 128 символов |

Успех `200`: в заголовке `Set-Cookie: session=...` и объект `User` в теле.

```http
HTTP/1.1 200 OK
Set-Cookie: session=Qm9hcmQtZGVjay1maW5hbC12MTI; HttpOnly; Secure; SameSite=Lax; Path=/
Content-Type: application/json

{ "id": "6f1c2a9e-...", "name": "Гульнара Нуртазина", "login": "g.nurtazina", "role": "officer", "departmentId": "library", "active": true, "telegramLinked": false, "mustChangePassword": false }
```

Ошибки:

| Статус | Код | Когда |
|---|---|---|
| 400 | `validation` | Нет логина или пароля |
| 401 | `login_failed` | Нет такого логина, неверный пароль или пользователь заблокирован. Ответ одинаковый во всех трёх случаях |
| 429 | `rate_limited` | 5 неудачных попыток за 15 минут на пару «IP + логин». Заголовок `Retry-After` |

Что делает фронт: при `mustChangePassword: true` ведёт на `/account`. Иначе ведёт на страницу из `?next=` (только относительный путь) или на домашнюю страницу роли.

Успешный вход обнуляет счётчик неудачных попыток для этой пары «IP + логин».

### 5.2. `POST /auth/logout` — выход

**Кто:** любой. Тела нет.

Ответ `204` без тела и `Set-Cookie: session=; Max-Age=0; Path=/`. Запись сессии удалите из базы. Если сессии и так нет, тоже `204`: выход должен быть идемпотентным.

### 5.3. `GET /auth/me` — кто вошёл

**Кто:** любой. Фронт вызывает этот запрос при каждой загрузке страницы, а ещё после смены пароля и после нажатия «Я отправил код» в Telegram.

| Статус | Тело | Когда |
|---|---|---|
| 200 | `User` | Сессия жива и пользователь активен |
| 401 | `{"error":{"code":"unauthorized",...}}` | Сессии нет, истекла или пользователь заблокирован |

Каждый успешный запрос продлевает сессию (раздел 2.3).

### 5.4. `POST /auth/password` — смена своего пароля

**Кто:** любой вошедший. **Экран:** `/account`.

```json
{ "current": "tmp-k3j9x2qa", "next": "new-strong-password" }
```

Фронт заранее проверяет, что новый пароль не короче 8 символов и совпадает с повтором. Повтор на сервер не уходит.

| Статус | Код | `field` | Когда |
|---|---|---|---|
| 204 | — | — | Пароль изменён |
| 400 | `wrong_password` | `current` | Текущий пароль неверный |
| 400 | `weak_password` | `next` | Новый короче 8 символов |
| 401 | `unauthorized` | — | Нет сессии |

После успеха:
- `must_change_password = false`;
- все **другие** сессии пользователя удаляются, текущая остаётся (R19). Человек не должен вылететь сразу после смены пароля.

Фронт после `204` запрашивает `GET /auth/me` и ждёт там `mustChangePassword: false`. Только после этого он снимет блокировку разделов.

## 6. Листы

### 6.1. `GET /sheets` — список листов

**Кто:** `officer`, `admin`. **Экраны:** `/office` (очередь отдела), `/admin` (все листы).

Параметры строки запроса:

| Параметр | Тип | Что делает |
|---|---|---|
| `status` | `SheetStatus` | Только листы с этим вычисленным статусом |
| `type` | `SheetType` | Только листы этого типа |
| `q` | string до 100 | Поиск по ФИО, группе, номеру (раздел 2.7) |
| `department` | `DeptId` | Только листы, в которые входит этот отдел |
| `markState` | `MarkState` | Вместе с `department`: только листы, где отметка этого отдела в этом состоянии |
| `page`, `pageSize` | integer | Раздел 2.6 |

Правила:
- У `officer` значение `department` берите **из сессии** и подставляйте всегда, даже если фронт прислал другое или не прислал ничего. Сотрудник видит только листы своего отдела.
- `markState` без `department` у `admin` вернёт `400 validation`. Фронт так не делает.
- При `markState=clear` в выборку входят и закрытые листы: на вкладке «Отмечены» сотрудник видит всё, что отметил. Строки закрытых листов фронт показывает с замком.
- Сортировка: новые сверху по `createdAt`.

Как фронт вызывает этот запрос:

```
# очередь библиотеки, вкладка «Ожидают», поиск «Ахметов», первая страница
GET /api/v1/sheets?department=library&markState=pending&q=Ахметов&page=1&pageSize=25

# учебная часть, вкладка «Есть задолженность»
GET /api/v1/sheets?status=debt&page=1&pageSize=25
```

Ответ `200`:

```json
{ "items": [ { "number": "2026-0142", "type": "graduation", "status": "debt", "...": "полный Sheet" } ], "total": 1 }
```

В `items` лежат полные объекты `Sheet` со всеми отметками: учебная часть показывает строку значков всех отделов.

### 6.2. `GET /sheets/mine` — листы студента

**Кто:** `student`. **Экран:** `/student`.

Ответ `200`: массив `Sheet` без пагинации (у студента их единицы).

Порядок важен:
1. открытые листы, новые сверху;
2. затем закрытые, недавно закрытые сверху.

Фронт крупно показывает первый открытый лист, а если открытых нет, первый закрытый. Остальные уходят в историю «Другие листы».

Другие роли получают `403 forbidden`.

### 6.3. `GET /sheets/summary` — сводка учебной части

**Кто:** `admin`. **Экран:** `/admin`, верхняя строка «Открыто листов 7, из них с долгом 3. Закрыто в этом году 41.»

```json
{ "active": 7, "withDebt": 3, "closed": 41 }
```

| Поле | Как считать |
|---|---|
| `active` | Листы с `closed_at IS NULL` |
| `withDebt` | Открытые листы, где есть хотя бы одна отметка `debt` |
| `closed` | Листы, у которых `closed_at` попадает в текущий календарный год по `Asia/Almaty` (с 1 января) |

### 6.4. `GET /sheets/{number}` — карточка листа

**Кто:** `admin` — любой лист. `officer` — только лист, в который входит его отдел. **Экран:** `/sheets/:number`.

Ответ `200`: `Sheet` и массив `audit` с записями журнала **только по этому листу**, новые сверху.

```json
{
  "number": "2026-0142",
  "type": "graduation",
  "status": "debt",
  "createdAt": "2026-10-26T09:00:00+05:00",
  "closedAt": null,
  "student": { "id": "c0a8012e-...", "name": "Айгерим Сапарова", "group": "ПО-2201" },
  "marks": [ "...как в 4.4" ],
  "audit": [
    { "at": "2026-10-29T14:15:00+05:00", "actor": "Жанар Абдрахманова", "sheet": "2026-0142", "department": "academic", "action": "clear" },
    { "at": "2026-10-28T09:15:00+05:00", "actor": "Гульнара Нуртазина", "sheet": "2026-0142", "department": "library", "action": "debt", "note": "Вернуть книгу «Python…»" },
    { "at": "2026-10-26T09:00:00+05:00", "actor": "Жанар Абдрахманова", "sheet": "2026-0142", "action": "create" }
  ]
}
```

Фронт показывает первые 20 записей журнала и кнопку «Показать все записи (N)». Пагинация здесь не нужна, отдавайте весь журнал листа.

| Статус | Код | Когда |
|---|---|---|
| 403 | `forbidden` | Запрос от студента |
| 404 | `not_found` | Листа нет, **или** сотрудник отдела запросил лист, в который его отдел не входит. Отвечайте 404, а не 403, чтобы не подтверждать, что такой лист существует |

### 6.5. `POST /sheets` — открыть лист

**Кто:** `admin`. **Экран:** `/admin`, форма «Открыть лист».

```json
{ "studentId": "c0a8012e-5d3b-4b8e-8f0a-1e2d3c4b5a69", "type": "dorm" }
```

Что сделать в одной транзакции:
1. проверить, что студент существует (R1);
2. проверить, что у него нет открытого листа этого типа (R2, уникальный частичный индекс);
3. взять следующий номер в году (R4);
4. скопировать отделы шаблона типа в `marks` со статусом `pending` (R3);
5. записать в журнал `create` от имени администратора.

Ответ `201`: созданный `Sheet`.

```json
{
  "number": "2026-0147",
  "type": "dorm",
  "status": "created",
  "createdAt": "2026-10-29T11:02:00+05:00",
  "closedAt": null,
  "student": { "id": "c0a8012e-...", "name": "Айгерим Сапарова", "group": "ПО-2201" },
  "marks": [ { "department": "dorm", "state": "pending" }, { "department": "accounting", "state": "pending" } ]
}
```

Фронт показывает «Лист № 2026-0147 открыт» и ссылку на карточку.

| Статус | Код | `field` | Когда |
|---|---|---|---|
| 400 | `validation` | `type` / `studentId` | Нет поля или неизвестный тип |
| 404 | `not_found` | — | Студента нет |
| 409 | `duplicate` | `type` | У студента уже открыт лист этого типа |

Сразу после открытия лист должен появиться в `GET /sheets` у всех отделов из шаблона и в `GET /sheets/mine` у студента.

### 6.6. `PUT /sheets/{number}/marks/{department}` — отметка отдела

**Кто:** только `officer`, только за свой отдел. **Экраны:** `/office` (кнопки в строке очереди) и `/sheets/:number` (блок «Отметка отдела»).

Нет задолженности:

```json
{ "state": "clear" }
```

Долг:

```json
{ "state": "debt", "note": "Вернуть «Компьютерные сети», инв. № 5512", "due": "2026-11-15" }
```

| Поле | Ограничения |
|---|---|
| `state` | `clear` или `debt` |
| `note` | Только при `debt`. Обязательно. После обрезки пробелов 1–200 символов. Фронт обрезает пробелы сам, сервер обязан проверить ещё раз |
| `due` | Только при `debt`. Необязательно. `YYYY-MM-DD`, не раньше сегодня по Алматы. Если не задан, поле не приходит |

Порядок проверок (первая сработавшая даёт ответ):

| Шаг | Проверка | Ответ при нарушении |
|---|---|---|
| 1 | Роль `officer` и `department` в URL совпадает с отделом из сессии (R5) | `403 forbidden` |
| 2 | Лист существует | `404 not_found` |
| 3 | Лист не закрыт (R7) | `409 closed` |
| 4 | Отдел входит в лист (R6) | `400 foreign_dept` |
| 5 | Тело верное: `state` из двух значений; для `debt` описание и срок по R8 | `400 validation` / `note_required` / `note_too_long` / `due_past`, с `field` |

Что сделать в одной транзакции:
1. записать отметку: при `clear` очистить `note` и `due` (R9), заполнить `updated_at` и `updated_by`;
2. если отметка ничего не меняет (то же состояние, текст и срок), не трогать журнал и сразу вернуть лист (R12);
3. записать в журнал `clear` или `debt`;
4. если теперь все отметки `clear`, заполнить `closed_at` и записать в журнал `close` от имени «Система» (R10).

После коммита (не внутри транзакции) отправить студенту сообщение в Telegram, если он подключён: при долге и при закрытии листа (раздел 12).

Ответ `200`: лист **после** изменения, со свежим `status` и `closedAt`. По `closedAt` фронт понимает, закрылся ли лист, и пишет «все отделы отметились, лист закрыт».

Повторная отметка закрытого листа обязана вернуть `409 closed`, даже если прислали `clear`.

## 7. Очередь отдела

### 7.1. `GET /queue/counts` — счётчики вкладок

**Кто:** `officer`. **Экран:** `/office`, цифры на вкладках «Ожидают 3 · С долгом 1 · Отмечены 5».

```json
{ "pending": 3, "debt": 1, "clear": 5 }
```

Считайте отметки отдела текущего сотрудника по всем листам: для `pending` и `debt` это открытые листы, для `clear` вместе с закрытыми. Цифры должны совпадать с `total` из `GET /sheets?department=…&markState=…` для той же вкладки.

### 7.2. `POST /queue/clear` — массовая отметка «нет задолженности»

**Кто:** `officer`. **Экран:** `/office`: сотрудник отмечает галочками несколько строк и нажимает «Отметить без задолженности».

```json
{ "numbers": ["2026-0143", "2026-0145", "2026-0146"] }
```

`numbers`: от 1 до 200 номеров.

Каждый номер обработайте **в своей транзакции** по правилам из 6.6 (R14). Ошибка одного листа не откатывает остальные.

Ответ `200`:

```json
{
  "updated": ["2026-0143", "2026-0146"],
  "failed": [ { "number": "2026-0145", "code": "closed" } ]
}
```

- Лист, где отметка уже `clear`, попадает в `updated` без новой записи журнала.
- Коды в `failed` берутся из таблицы ошибок: `not_found`, `closed`, `foreign_dept`.
- Если какой-то лист закрылся этой отметкой, так же, как в 6.6, запишите `close` и отправьте уведомление.

## 8. Студенты

### 8.1. `GET /students` — справочник

**Кто:** `admin`. **Экраны:** `/admin/students` (таблица) и поиск студента в форме «Открыть лист» на `/admin`.

| Параметр | Что делает |
|---|---|
| `q` | Поиск по ФИО, группе, логину |
| `page`, `pageSize` | Раздел 2.6. Поиск в форме открытия листа шлёт `pageSize=8` и только когда введено от 2 символов |

Сортировка по ФИО по алфавиту (русская сортировка, `COLLATE "ru-RU-x-icu"` или аналог).

```json
{
  "items": [
    { "id": "c0a8012e-...", "userId": "9b2e4f61-...", "name": "Айгерим Сапарова", "group": "ПО-2201", "login": "a.saparova", "activeSheets": 1 }
  ],
  "total": 1
}
```

### 8.2. `POST /students` — добавить студента

**Кто:** `admin`.

```json
{ "name": "Мадина Ержанова", "group": "ПО-2203", "login": "m.erzhanova" }
```

| Поле | Ограничения |
|---|---|
| `name` | 3–120 символов после обрезки пробелов |
| `group` | 2–20 символов после обрезки пробелов |
| `login` | `^[a-z0-9._-]{3,64}$`, уникален среди всех пользователей. Фронт переводит его в нижний регистр |

Что сделать: создать `users` (роль `student`, `must_change_password = true`, временный пароль) и `students`.

Ответ `201`:

```json
{
  "student": { "id": "...", "userId": "...", "name": "Мадина Ержанова", "group": "ПО-2203", "login": "m.erzhanova", "activeSheets": 0 },
  "temporaryPassword": "Kp7wQm2xRt"
}
```

Временный пароль: 10 случайных символов без похожих знаков (`0O1lI`). Он виден только в этом ответе: фронт показывает его один раз, в базе хранится только хеш.

| Статус | Код | `field` |
|---|---|---|
| 400 | `validation` | `name` / `group` / `login` |
| 409 | `login_taken` | `login` |

### 8.3. `PATCH /students/{id}` — изменить ФИО или группу

**Кто:** `admin`. **Экран:** кнопка «Изменить» в строке справочника.

```json
{ "name": "Мадина Ержанова", "group": "ПО-2301" }
```

Оба поля необязательны; присылаются оба. Логин не меняется.

Ответ `200`: обновлённый `Student`. Ошибки: `400 validation` с `field`, `404 not_found`.

Открытые листы продолжают показывать новое ФИО и группу: они берутся из `students` и `users` в момент ответа. Подписи сотрудников в старых отметках не меняются (`marks.by` хранит имя на момент отметки).

### 8.4. `POST /students/import` — импорт из CSV

**Кто:** `admin`. **Экран:** `/admin/students`, «Импорт из CSV».

Запрос: `multipart/form-data`, файл в поле с именем **`file`**.

Формат файла:
- UTF-8, BOM допускается;
- разделитель `;` или `,`, определяйте по первой строке;
- колонки по порядку: `name`, `group`, `login`;
- первая строка может быть заголовком `name;group;login`;
- до 2 МБ и 2000 строк.

Пример:

```csv
name;group;login
Алия Кенжебаева;ПО-2301;a.kenzhebaeva
Тимур Есенов;ПО-2203;t.esenov
```

Каждую строку проверяйте отдельно, хорошие создавайте, плохие пропускайте:

| Причина пропуска | Код в `skipped` |
|---|---|
| Пустое или слишком короткое поле, логин не по шаблону | `validation` |
| Ячейка начинается с `=`, `+`, `-`, `@` (защита от формул в Excel) | `validation` |
| Логин уже занят | `login_taken` |

Ответ `200`:

```json
{
  "created": [
    { "student": { "id": "...", "userId": "...", "name": "Алия Кенжебаева", "group": "ПО-2301", "login": "a.kenzhebaeva", "activeSheets": 0 }, "temporaryPassword": "Hn4vRt8kWq" }
  ],
  "skipped": [ { "line": 3, "code": "login_taken" } ]
}
```

`line` — номер строки в файле, считая с 1 и **включая** заголовок.

Из `created` фронт сам собирает CSV «логин;пароль» для учебной части. Сервер файл с паролями не формирует и пароли не хранит.

Когда весь файл отклоняется: `400 bad_file` (не UTF-8, больше 2 МБ или 2000 строк, нет трёх колонок). Лимит частоты: 5 импортов в час на пользователя, затем `429`.

## 9. Сотрудники

### 9.1. `GET /users` — список сотрудников

**Кто:** `admin`. **Экран:** `/admin/staff`.

Только `officer` и `admin`, без студентов. Сортировка по ФИО. Фронт просит `pageSize=50`.

```json
{
  "items": [
    { "id": "...", "name": "Евгений Ким", "login": "e.kim", "role": "officer", "departmentId": "accounting", "active": true, "telegramLinked": false, "mustChangePassword": false }
  ],
  "total": 7
}
```

### 9.2. `POST /users` — добавить сотрудника

**Кто:** `admin`.

```json
{ "name": "Мария Ли", "login": "m.li", "role": "officer", "departmentId": "dorm" }
```

```json
{ "name": "Ерлан Нуров", "login": "e.nurov", "role": "admin" }
```

| Поле | Ограничения |
|---|---|
| `name` | 3–120 символов |
| `login` | `^[a-z0-9._-]{3,64}$`, уникален |
| `role` | `officer` или `admin` |
| `departmentId` | Обязателен при `officer`. При `admin` фронт его не присылает; если пришёл, игнорируйте |

Ответ `201`:

```json
{
  "user": { "id": "...", "name": "Мария Ли", "login": "m.li", "role": "officer", "departmentId": "dorm", "active": true, "telegramLinked": false, "mustChangePassword": true },
  "temporaryPassword": "Wx3kPn9tRa"
}
```

| Статус | Код | `field` |
|---|---|---|
| 400 | `validation` | `name` / `login` / `role` |
| 400 | `department_required` | `departmentId` |
| 409 | `login_taken` | `login` |

### 9.3. `PATCH /users/{id}` — изменить сотрудника

**Кто:** `admin`. **Экран:** выпадающий список отдела в строке и кнопка «Заблокировать» / «Разблокировать».

Фронт присылает одно поле за раз:

```json
{ "departmentId": "it" }
```

```json
{ "active": false }
```

| Поле | Правила |
|---|---|
| `name` | 3–120 символов |
| `departmentId` | Только для `officer`. Меняет, какие листы сотрудник видит с этого момента. Старые отметки не трогает |
| `active` | `false` блокирует: удалить все сессии пользователя (R19), дальше вход даёт `login_failed`. `true` разблокирует |

Ответ `200`: обновлённый `User`.

| Статус | Код | Когда |
|---|---|---|
| 400 | `validation` | Неверное значение, или `departmentId` для администратора |
| 403 | `forbidden` | Администратор блокирует сам себя (R18). Фронт у своей строки этой кнопки не показывает |
| 404 | `not_found` | Нет сотрудника с таким `id` (студенты здесь тоже `404`) |

### 9.4. `POST /users/{id}/reset-password` — новый временный пароль

**Кто:** `admin`. **Экраны:** «Новый пароль» в `/admin/staff` (передаётся `id` сотрудника) и в `/admin/students` (передаётся `userId` студента).

Тела нет. Ответ `200`:

```json
{ "temporaryPassword": "Qz8mVt4nKp" }
```

Что сделать: новый временный пароль, `must_change_password = true`, удалить **все** сессии этого пользователя (R19).

| Статус | Код | Когда |
|---|---|---|
| 403 | `forbidden` | Администратор сбрасывает пароль самому себе. Свой пароль меняют через `POST /auth/password`. Фронт эту кнопку у своей строки не показывает |
| 404 | `not_found` | Нет пользователя |

**Кто:** `admin`. **Экраны:** `/admin/templates` (матрица) и подсказка «Отделы по шаблону: …» в форме открытия листа.

Ответ `200`: объект `Templates` (раздел 4.6).

**Кто:** `admin`. Фронт отправляет запрос сразу после каждого щелчка по галочке матрицы.

```
PUT /api/v1/templates/dorm
```


## 12. Telegram

### 12.1. `POST /telegram/link` — получить код привязки

**Кто:** `student`. **Экран:** `/student`, кнопка «Подключить».

Тела нет. Ответ `200`:

```json
{ "code": "4821", "botUrl": "https://t.me/aitu_clearance_bot?start=4821", "expiresAt": "2026-10-29T11:17:00+05:00" }
```

- Код из 4–6 цифр, живёт 15 минут.
- Новый запрос заменяет предыдущий код этого студента.
- `botUrl` фронт открывает как обычную ссылку.

### 12.2. `DELETE /telegram/link` — отвязать

**Кто:** `student`. Ответ `204`. После него `GET /auth/me` возвращает `telegramLinked: false`.

### 12.3. Сторона бота (не HTTP API, но тоже работа бэкенда)

1. Бот получает `/start 4821`.
2. Находит неистёкший код, пишет `users.telegram_chat_id`, удаляет код, отвечает «Подключено».
3. Неизвестный или истёкший код: бот отвечает «Код не найден или устарел. Получите новый на сайте».

Фронт после нажатия «Я отправил код» вызывает `GET /auth/me`. Поле `telegramLinked` должно стать `true` сразу, как только бот обработал код.

### 12.4. Какие сообщения слать

| Событие | Текст (пример) |
|---|---|
| Отдел поставил долг | «Библиотека: вернуть «Python. Основы программирования», инв. № 4471. Срок: 5 ноября. Каб. 104, пн–пт 9:00–17:00» |
| Лист закрыт | «Обходной лист № 2026-0142 закрыт. Проверка: https://<домен>/verify/2026-0142» |

Отметки «нет задолженности» не присылайте: в сезон выпуска это десятки сообщений. Ошибка отправки в Telegram не откатывает отметку, сообщение ставьте в очередь после коммита.

## 13. Публичная проверка

### 13.1. `GET /public/verify/{number}`

**Кто:** кто угодно, без сессии. **Экран:** `/verify/:number`; сюда ведёт QR-код с печати.

Ответ **всегда `200`**, даже если листа нет. Варианты тела описаны в разделе 4.7.

| Ситуация | Тело |
|---|---|
| Листа нет | `{ "found": false, "closed": false }` |
| Лист есть, но не закрыт | `{ "found": true, "closed": false, "shortName": "Айгерим С." }` |
| Лист закрыт | все поля, включая `number`, `type`, `closedAt`, `departments` |

- Фронт проверяет формат номера `^\d{4}-\d{4}$` до запроса. Если номер всё же пришёл в другом формате, отвечайте `{ "found": false, "closed": false }`.
- Лимит: 30 запросов в минуту на IP, затем `429` с `Retry-After`.
- Только поля из таблицы: никаких ФИО полностью, групп, описаний долгов, сотрудников (R20).

## 14. Сквозные сценарии: какие запросы идут подряд

### 14.1. Первый вход сотрудника с временным паролем

```
POST /auth/login            {login:"m.li", password:"Wx3kPn9tRa"}   → 200 User{mustChangePassword:true}
                                                                     фронт уходит на /account
POST /auth/password         {current:"Wx3kPn9tRa", next:"…"}         → 204
GET  /auth/me                                                        → 200 User{mustChangePassword:false}
GET  /queue/counts                                                   → 200
GET  /sheets?department=dorm&markState=pending&page=1&pageSize=25    → 200
```

### 14.2. Жизнь одного листа

```
[учебная часть]  GET  /students?q=Нурлан&pageSize=8                  → студент найден
                 POST /sheets {studentId, type:"graduation"}         → 201, number=2026-0147
[студент]        GET  /sheets/mine                                   → лист, 6 × pending
[библиотека]     PUT  /sheets/2026-0147/marks/library {state:"debt", note:"…"} → 200, status=debt
                                                                     → Telegram студенту о долге
[5 отделов]      PUT  /sheets/2026-0147/marks/<dept> {state:"clear"} → 200 каждый
[библиотека]     PUT  /sheets/2026-0147/marks/library {state:"clear"} → 200, status=closed, closedAt заполнен
                                                                     → журнал: close от «Система»
                                                                     → Telegram студенту о закрытии
[студент]        GET  /sheets/mine                                   → печать и QR на экране
[кто угодно]     GET  /public/verify/2026-0147                       → found, closed, shortName
[библиотека]     PUT  /sheets/2026-0147/marks/library {...}          → 409 closed
```

### 14.3. Сессия истекла посреди работы

```
PUT /sheets/2026-0145/marks/library {state:"clear"}   → 401 unauthorized
                                                        фронт: /login?next=%2Foffice
POST /auth/login                                      → 200, фронт возвращает на /office
```

## 15. Частые ошибки реализации

| Ошибка | Чем кончится на фронте | Как правильно |
|---|---|---|
| Тело в ответе 204 или 204 вместо JSON там, где ждут объект | Фронт получит пустоту и упадёт на экране | 204 только у logout, password, telegram DELETE, всегда без тела |
| Ошибка не в формате `{error:{code,message}}` или код вне списка | Человек увидит не тот текст ошибки | Один обработчик ошибок на всё приложение, коды строго из раздела 2.8 |
| HTML вместо JSON на `/api/*` (неверно настроен прокси, отдаёт `index.html`) | Пустые экраны без ошибки | `/api` проксируется на бэкенд раньше правила «всё остальное → index.html» |
| Дата без часового пояса | Время съедет на 5 часов | ISO 8601 с `Z` или `+05:00` |
| «Сегодня» по UTC | С 00:00 до 05:00 срок «вчера» пройдёт проверку | Дата по `Asia/Almaty` |
| `status` хранится в таблице | Разъедется с отметками | Вычислять по R11 при каждом ответе |
| Отметки в произвольном порядке | Значки отделов прыгают между строками | Канонический порядок из 3.1 |
| Номер `2026-142` без нулей | QR и поиск не совпадут | Всегда 4 цифры после дефиса |
| После отметки возвращается старый лист | Фронт не узнает, что лист закрылся | Вернуть лист после изменения |
| Сотруднику доступны чужие листы через параметр `department` | Утечка данных | Отдел только из сессии |
| На чужой лист сотруднику 403 | Подтверждает существование листа | 404 |
| `Secure` cookie на http://localhost | Вход «проходит», но сессия не держится | Без `Secure` в разработке |
| Поле `userId` не пришло у студента | Кнопка «Новый пароль» не работает | `userId` обязателен |
| Шаблон после PUT не возвращается целиком | Галочки встанут неверно | Вернуть все пять типов |
| Telegram отправляется внутри транзакции | Сбой Telegram откатит отметку | Отправка после коммита |

## 16. Как проверить готовность

### 16.1. Руками через curl

```bash
# вход: cookie сохранится в файл
curl -i -c jar.txt -H 'X-Requested-With: fetch' -H 'Content-Type: application/json' \
  -d '{"login":"admin","password":"…"}' http://localhost:8000/api/v1/auth/login

# кто я
curl -b jar.txt -H 'X-Requested-With: fetch' http://localhost:8000/api/v1/auth/me

# изменение без защитного заголовка обязано вернуть 403
curl -i -b jar.txt -H 'Content-Type: application/json' -d '{"studentId":"x","type":"dorm"}' \
  http://localhost:8000/api/v1/sheets

# публичная проверка без cookie
curl http://localhost:8000/api/v1/public/verify/2026-0139
```

### 16.2. Вместе с фронтом

```bash
cd frontend
cp .env.example .env        # VITE_PROXY_TARGET=http://localhost:8000
npm install
npm run dev                 # http://localhost:5173/login
```

Чек-лист:

| # | Действие | Ожидание |
|---|---|---|
| 1 | Вход администратором | `/admin`, сводка с цифрами |
| 2 | Добавить сотрудника библиотеки | Показан временный пароль; сотрудник входит и попадает на смену пароля |
| 3 | Добавить студента, импортировать CSV из 3 строк с одним занятым логином | Создано 2, пропущена 1 с «Такой логин уже занят» |
| 4 | Открыть лист «Выпуск», затем второй такой же | Второй раз «У студента уже есть открытый лист этого типа» |
| 5 | Сотрудник библиотеки ставит долг без описания прямым запросом | `400 note_required` |
| 6 | Сотрудник подставляет в URL чужой отдел | `403` |
| 7 | Все отделы ставят «нет задолженности» | Лист закрыт, в журнале запись «Система» |
| 8 | Изменить отметку закрытого листа | `409 closed` |
| 9 | Открыть `/verify/<номер>` без входа | Имя с инициалом, тип, дата, отделы; ни группы, ни долгов |
| 10 | 6 неудачных входов подряд | `429` и «Слишком много попыток» |
| 11 | Заблокировать сотрудника, у которого открыта вкладка | Следующее его действие уводит на вход |

### 16.3. Автоматическая приёмка

В `frontend/e2e/` лежат сценарии Playwright на все роли. Сейчас они ходят в фейковый сервер `frontend/e2e/fakeApi.ts`, который реализует этот контракт. Фейк ведёт себя так, как должен вести себя ваш бэкенд, поэтому его код можно читать как ещё одну, исполняемую спецификацию. Если сомневаетесь, что вернуть в каком-то случае, посмотрите, что возвращает фейк.
