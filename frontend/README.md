# Электронный обходной лист колледжа AITU: фронтенд

Дипломный проект студентов колледжа Astana IT University. Это не официальный сервис университета. Здесь лежат публичный лендинг, вход, кабинеты студента, сотрудника отдела и учебной части, а также страница проверки подлинности по QR-коду.

Фронтенд работает только с настоящим API. Моковых данных в проекте нет. Контракт API и ТЗ для бэкенда: [docs/backend](../docs/backend/README.md).

## Запуск

Нужен Node.js 18 или новее и запущенный бэкенд.

```bash
cd frontend
cp .env.example .env      # при необходимости поменяйте адрес бэкенда
npm install
npm run dev
```

Откройте http://localhost:5173. Запросы к `/api` Vite проксирует на адрес из `VITE_PROXY_TARGET` (по умолчанию `http://localhost:8000`). Фронт и API оказываются на одном origin, поэтому cookie сессии работает без настройки CORS.

| Команда | Что делает |
|---|---|
| `npm run dev` | дев-сервер с горячей перезагрузкой и прокси на бэкенд |
| `npm run build` | проверка типов и сборка в `dist/` |
| `npm test` | тесты правил, сценариев, HTTP-клиента и правила зависимостей |

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `VITE_PROXY_TARGET` | `http://localhost:8000` | адрес бэкенда для прокси в режиме разработки |
| `VITE_API_URL` | `/api/v1` | базовый путь API в браузере; меняйте, только если API на другом домене |

В проде отдавайте `dist/` и API с одного домена, а `/api` проксируйте на бэкенд (nginx или аналог). Все маршруты, кроме `/api`, должны отдавать `index.html`: роутинг на стороне браузера.

## Экраны

| Адрес | Кто | Что |
|---|---|---|
| `/` | все | лендинг для администрации колледжа |
| `/login` | все | вход по логину и паролю |
| `/verify/:номер` | все, без входа | проверка подлинности закрытого листа |
| `/student` | студент | свой лист: что держит, долги, PDF, Telegram |
| `/office` | сотрудник отдела | очередь своего отдела, отметки, долги, массовая отметка |
| `/sheets/:номер` | отдел, учебная часть | карточка листа с журналом; отдел ставит отметку отсюда |
| `/admin` | учебная часть | сводка, открытие листа, все листы |
| `/admin/students` | учебная часть | справочник студентов, импорт CSV, сброс пароля |
| `/admin/staff` | учебная часть | сотрудники, отделы, блокировка, сброс пароля |
| `/admin/templates` | учебная часть | какие отделы входят в лист каждого типа |
| `/admin/audit` | учебная часть | журнал действий |
| `/account` | любой вошедший | смена пароля; с временным паролем пускает только сюда |

Вёрстка проверена на ширине 390, 768, 1024 и 1440 px, на русском и казахском.

## Архитектура

Код разложен по слоям чистой архитектуры. Зависимости направлены только внутрь.

```
presentation  →  application  →  domain
                     ↑
              infrastructure
```

| Слой | Папка | Что внутри |
|---|---|---|
| Домен | `src/domain/` | сущности (лист, отметка, пользователь, студент), коды ошибок, правила проверки форм |
| Сценарии | `src/application/` | порт `ClearanceApi` (что интерфейс может попросить у сервера) и сценарии, которые проверяют данные до отправки |
| Инфраструктура | `src/infrastructure/` | `httpApi.ts`: реализация порта на `fetch`, перевод ответов сервера в доменные ошибки |
| Интерфейс | `src/presentation/` | React: страницы, компоненты, авторизация и защита маршрутов, i18n, стили |

Слои соединяются в `src/main.tsx`. Тест `src/architecture.test.ts` падает, если слой импортирует то, что ему не положено.

Как устроены данные на страницах: хук `useQuery` из `src/presentation/services.tsx` загружает данные, показывает загрузку и ошибку и перезапрашивает их, когда пользователь возвращается на вкладку. Права проверяет сервер. Фронт только не показывает чужие разделы и уводит на вход при истёкшей сессии.

## Сквозные тесты (e2e)

```bash
npm run e2e                 # 81 сценарий в Chromium, отчёт в e2e-report/
npx playwright test -g "журнал"   # только сценарии с этим словом в названии
```

Сценарии лежат в `e2e/`. Бэкенд в них фейковый (`e2e/fakeApi.ts`): он хранит состояние и соблюдает контракт `docs/backend/openapi.yaml` и правила из ТЗ, кроме отзыва сессий при сбросе и смене пароля (R19). В продукт он не попадает. Когда появится настоящий бэкенд, эти же сценарии служат приёмкой: он должен вести себя так же.

| Файл | Что проверяет |
|---|---|
| `auth.spec.ts` | вход всех ролей, ошибки, лимит попыток, блокировка, `next`, чужие разделы, истёкшая сессия, временный пароль |
| `admin.spec.ts` | сотрудники, студенты, импорт CSV (занятые логины, формулы), открытие листа, дубль, фильтры, пагинация, шаблоны, журнал |
| `officer.spec.ts` | очередь своего отдела, отметка, долг и его проверки, правка и погашение, массовая отметка, поиск, закрытые листы, карточка |
| `student.spec.ts` | что держит лист, закрытый лист (печать, QR, PDF, ссылка), печатная форма, Telegram, пустое состояние, история |
| `journey.spec.ts` | полный путь листа через шесть отделов в отдельных окнах и проверка подлинности посторонним |
| `public.spec.ts` | проверка документа, лендинг, «уменьшить движение», 404 |
| `resilience.spec.ts` | нет сети, ошибка сервера, медленный ответ, повтор |
| `experience.spec.ts` | адаптив на 320–1440 px, доступность axe (WCAG 2.1 AA) на 13 экранах, клавиатура, казахский язык |
| `worst-case.spec.ts` | худшие реалистичные данные: длинные ФИО, диакритика, ссылки и `<script>` в описании долга, 1000 записей журнала |



- Правила форм: долг с описанием до 200 символов и сроком не в прошлом, пароль от 8 символов с повтором, логин латиницей.
- Сценарии: неверные данные не уходят на сервер, у администратора отдел не отправляется.
- HTTP-клиент: правильные пути и методы, cookie и защитный заголовок, пустые параметры не попадают в запрос, коды ошибок сервера становятся доменными ошибками, 401 уводит на вход.
- Правило зависимостей между слоями.

## Бренд

Логотип взят с astanait.edu.kz. Из файла удалены метаданные Illustrator, белая версия для тёмного фона сделана перекраской того же файла. Цвета: тёмно-синий `#001c46` и голубой `#1385e5`. Для кнопок и синего текста используется `#0a66b8`, потому что белый текст на `#1385e5` не проходит WCAG AA.

## Перед сдачей

- Казахские тексты написаны без носителя языка. Их нужно вычитать.
- Перед публикацией в интернете получите согласие колледжа на использование логотипа.
